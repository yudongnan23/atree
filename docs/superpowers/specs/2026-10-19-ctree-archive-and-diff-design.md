# ctree：自动归档、旧会话折叠、diff 浮窗 — 设计

日期：2026-10-19
基于：`2026-10-19-ctree-sidebar-design.md`（下称"原设计"）。本文只写变化；没提到的行为保持原设计和现有实现不变。Codex 支持不在本次范围（用户决定）。

## 意图

侧栏会话一多就很难找。用户要的是 Desktop 那样的整洁：只看最近在用的 project 和最近的会话，旧的收起来但随时能翻出来；并且能随时按一个键看某个会话所在仓库改了什么。

## 一、归档与折叠

两种粒度的归档并存（用户决定）：

| | 去哪里 | 触发 |
|---|---|---|
| **会话归档** | 留在自己的 project 下，收进该 project 的「更早的会话」折叠行 | 手动：在会话行按 `a` |
| **project 归档** | 移到底部已有的「已归档」分组 | 自动：30 天无活动；手动：在 project 行按 `a` |

### 定义

- **会话活动时间**：现有 `LastActive`（transcript 文件 mtime，运行中会话取 `StatusUpdatedAt` 与之较大者）。
- **project 活动时间**：该 project 下所有会话（含已归档会话）活动时间的最大值。
- **正在运行**：状态为 `●` `◆` `○` `↗` 之一。
- 阈值：**7 天**、**30 天**，相对当前时间，写成常量，不做配置。

### project 层

- 主列表只显示"未归档"的 project，按 project 活动时间从新到旧排序（现有行为）。
- **自动归档**：project 活动时间早于 30 天前，且没有任何正在运行的会话 → 归入「已归档」。纯计算，不写状态；有新活动即自动回到主列表。
- **手动归档**：在 project 行按 `a`。
  - 若该 project 有任何正在运行的会话 → 拒绝，toast：`这个 project 还有正在运行的会话，请先关闭`。（我的决定：避免一次结束多个会话）
  - 否则记录 `ArchivedProjects[cwd] = 当前时间`。
  - 若之后 project 活动时间晚于这个归档时间（有了新聊天），自动回到主列表，并清掉该记录。（我的决定，与自动归档一致）
- 「已归档」分组（底部，默认折叠，现有）：现在内容是**被归档的 project**，每个 project 一行、默认折叠，展开后列出它的**全部**会话（不再做 7 天折叠），排序同主列表。在其中的 project 行按 `a` = 取消手动归档；对自动归档的 project 按 `a` 给 toast：`30 天内没有活动的 project 会自动归档，打开其中一个会话即可恢复`。
- 从「已归档」里打开任意会话 → 该 project 产生新活动 → 自动回到主列表（同时清掉它的手动归档记录）。

### 会话层（主列表中的 project 下）

- 直接显示：最近 7 天内有活动的会话 + 所有正在运行的会话，且未被手动归档。
- 其余（7 天以前的、以及手动归档的，不论新旧）收进一行：`  … 更早的 N 个会话`（N 为其中会话数）。没有这类会话则不显示这一行。
- 该行按 `⏎`/点击/`→` 展开，`←` 或再按 `⏎` 收起；展开状态按 project 持久化（`ExpandedOlder[cwd]`）。展开后其中会话排在这一行下面，排序同上。
- 若 project 7 天内没有可直接显示的会话，它下面只有这一折叠行。
- 会话内顺序不变：正在运行的在前，其余按活动时间从新到旧。
- **会话手动归档**（`a`）：
  - 正在运行（在 ctree 里）的：沿用现有确认 `归档会结束这个会话，继续？(y/n)`，确认后结束并归档。在别处运行的：沿用现有拒绝。
  - 已归档会话在「更早的」里用暗色标题显示，以便和普通旧会话区分。（我的决定）
  - 打开一个已归档会话 → 自动取消归档（现有行为）；在其上再按 `a` 也取消归档。
- 现有 `state.json` 里的 `archived` 会话记录直接按新语义解释（回到各自 project 的「更早的」里），无需迁移。

## 二、diff 浮窗

### 打开方式

- 侧栏：光标在会话行或 project 行上按 `d` → 看该会话/project 的目录。
- 右边 Claude 里：`⌥d` → 看当前显示在右边的会话的目录（tmux `bind -n M-d`，无前缀；取右侧窗格进程的当前目录 `#{pane_current_path}`）。若右边是占位界面，`⌥d` 不做事。
- 以 tmux 浮窗（`display-popup -E`，约 90% 宽高）运行 `ctree diff <dir>`；`q`/`esc` 关闭，回到原焦点，不影响任何会话。
- 不是 git 仓库：浮窗显示 `这个目录不是 git 仓库`，按任意键关闭。

### 内容（用户选定方案 A：完整目录树）

```
 zone · feat/snapshot-optimize · 3 个文件修改，2 个新增，1 个删除
┌──────────────────────────────┬─────────────────────────────────────┐
│ ▸ .github                    │ internal/snapshot/refresh.go        │
│ ▾ cmd  1                     │ @@ -42,9 +42,14 @@                   │
│   ▾ zone-admin  1            │ -  snap, err := loadAll(ctx)        │
│     M main.go                │ +  snap, err := cache.Get(ctx, key) │
│ ▾ internal  5                │ ...                                 │
│   ▾ snapshot  3              │                                     │
│     M refresh.go   ◀ 选中     │                                     │
│     A refresh_cache.go       │                                     │
│   ▾ zone  2                  │                                     │
│     D legacy.go              │                                     │
│   go.mod                     │                                     │
└──────────────────────────────┴─────────────────────────────────────┘
 ↑↓ 选文件  ←→ 折叠  tab 切到 diff 滚动  c 只看改动  q 关闭
```

- **顶栏**：project 名 · 当前分支（detached 时显示短 hash）· 统计 `N 个文件修改，N 个新增，N 个删除`（为 0 的项省略；全为 0 显示 `没有未提交的改动`）。
- **左：目录树**，以仓库根（`git rev-parse --show-toplevel`）为根：
  - 范围：已跟踪文件 + 未跟踪且未被忽略的文件 + 已删除的跟踪文件。被 `.gitignore` 忽略的不显示。
  - 颜色：修改 `M` 黄 `#e0af68`；新增 `A`（含未跟踪、已暂存新增）绿 `#9ece6a`；删除 `D` 红 `#f7768e` 加删除线；未改动文件和目录为灰白。重命名按"旧路径 D + 新路径 A"显示。
  - 含改动的目录默认展开，并在名字后标出其下改动文件数；其余目录默认折叠。目录排在文件前，各自按名字排序。
  - `c` 切换"只看改动"（只保留改动文件及其上级目录）。
  - 默认选中第一个改动文件；没有改动时选中第一行。
- **右：选中文件的 diff**：
  - 修改/删除：相对 `HEAD` 的改动（暂存 + 未暂存合并）。
  - 未跟踪新文件：整个文件作为新增显示。
  - 未改动文件：显示文件内容（只读预览）。
  - 二进制：显示 `二进制文件`。
  - 着色：`+` 绿、`-` 红、`@@` 蓝、文件头蓝。由 ctree 自己着色，不依赖 `delta`。
  - 选中目录时右边显示目录下改动文件列表（或为空）。
- **按键**：`↑↓`/`jk` 在树中移动；`←→` 折叠/展开目录；`⏎` 展开/折叠目录；`tab` 在树与 diff 之间切换焦点，diff 焦点下 `↑↓`/`jk`/`PgUp`/`PgDn`/`g`/`G` 滚动；`c` 只看改动；`q`/`esc` 关闭。
- 浮窗打开时读取一次 git 状态，不自动刷新（用户要的是"按键查看"，不是实时盯着）。

### 限制

- git 只知道目录整体的未提交改动，**无法区分是哪个会话改的**；会话里已经 commit 的改动不显示（用户已确认"看 diff 就行"）。

## 不做

- Codex 支持。
- 阈值配置项。
- diff 浮窗里的暂存、提交、回滚等写操作（只读）。
- 会话产生的 commit 历史。

## 审阅后补充的决定（我的决定）

- `⌥d` 判断右边是否为占位界面：读窗格的 `@ctree_role` 标签。
- 手动归档的 project 因新活动回到主列表时，由侧栏清掉 `ArchivedProjects[cwd]` 并保存（`tree.Build` 保持纯函数）。判断"有新活动"时留 10 秒余量，避免关闭会话后 Claude 晚写一笔 transcript 导致刚归档的 project 立刻弹回。
- 「已归档」里的 project 展开状态单独存 `ArchivedOpen[cwd]`，默认折叠，不复用主列表的 `Collapsed`。
- 在「已归档」里的会话行按 `a`：归档/取消归档这一个会话，与主列表一致。
- 既被手动归档、又超过 30 天的 project，按 `a` 时给自动归档的提示。
- 还没有任何提交的仓库：diff 浮窗把所有文件当作新增显示。
- `⌥d` 会被 tmux 全局拦截；若 Claude Code 自身用到 Alt-d（如向后删词），在 ctree 里会失效。按设计保留，README 注明。

## 留给实现者
